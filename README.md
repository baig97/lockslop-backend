# Lockslop backend

Next.js 16 API, Better Auth OAuth Provider, Drizzle and Neon Postgres.

## Development

Set `.env.local`: `DATABASE_URL` (pooled), `DATABASE_URL_UNPOOLED` (direct), `BETTER_AUTH_URL`, `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `EXTENSION_IDS` `YOUTUBE_DATA_API_KEY` and `TYPESAFE_API_KEY`. Never expose these secrets in extension builds. `OAUTH_EXTENSION_CLIENT_ID` is generated by registration if absent.

Run `npm install`, `npm run db:migrate`, `npm run db:seed`, `npm run auth:register-extension`, then `npm run dev`. Google uses a Web application client with callback `${BETTER_AUTH_URL}/api/auth/callback/google`.

Auth and OAuth Provider tables live in `auth`; content tables live in `public`. IDs use UUID v4. The extension is a first-party public OAuth client with exact redirect URLs and required S256 PKCE. Dynamic registration and client administration are disabled. Provider-managed opaque access tokens and rotating refresh tokens replace custom handoffs; users must sign in again after migrating. Google browser sessions are separate from extension OAuth tokens.

## Combined overview

`GET /api/v1/youtube/videos/:videoId/overview` returns the runtime-validated `VideoOverviewDto` from `lib/contracts/overview.ts`: entity identity, community counts and signal counts, optional authenticated viewer vote, and AI results. No raw provider payload or private feedback is returned. Invalid supplied credentials return 401; omitting credentials returns an anonymous overview. Existing contribution routes retain ownership and capability checks.

The extension mirrors the contract using `node scripts/sync-contract.mjs` in its repository; `--check` detects drift. One initial overview request populates both tabs and the personal vote.

`content_payloads` has one raw JSONB resource per entity (the YouTube `items[0]` video object, without the list response envelope), a provider, revision UUID, ready/stale status and creation/update times. `ai_content_signals` has one score per entity/key, bounded to [0,1], tagged with payload revision and generator version. Signal identity and generation rules live in code, separately from user-selected signals. Only YouTube videos are currently supported.

A complete signal set matching the payload revision and no more than one calendar month old is returned immediately, including results produced by older generator versions. Expired scores regenerate synchronously during the overview request under the existing lock; ready payloads are reused. All five rows must be fresh. Failed regeneration returns unavailable AI with community results intact, without serving expired scores. A payload without current signals is mapped into minimal generator input and reused. Missing or stale payloads are fetched with YouTube Data API v3, saved, then analyzed. The explicit mapper sends title, description, optional tags, publication time, optional language/live hints raw/parsed duration and sampled viewer comments to Jev. IDs, creator identity, imagery, engagement, licensing and technical settings are excluded. Missing optional evidence becomes null; malformed or oversized (32 KB pretty JSON) input is rejected. Provider metadata does not contain video/audio content or transcripts.

Generation uses direct Neon connections for session advisory locks (transaction poolers cannot preserve these locks), a second cache check, bounded lock waits, a five-second provider timeout, and atomic signal-set writes. Provider failure preserves community results; generation failure preserves the successfully fetched payload. A short process-local failure cooldown complements the route's shared database request limit.

## Generator and release preparation

`deriveAiSignals` composes an allowlist mapper, research-based context template (`lib/ai/youtube-video.context.ts`) and entity-independent TypeSafe runner. Each question uses structured task/signal/evidence-scope instructions and five standalone criteria with evidence/uncertainty fields. Signal definitions are not duplicated across levels. AI filler explicitly requires both AI-use evidence and observable filler; reuse requires little original contribution without inferring infringement. Five Score questions are batched into one request; scores are normalized by dividing by four, without using confidence. They measure **strength of metadata and supporting comment evidence**, not a calibrated probability of slop or analysis of the actual video. All five scores are stored; frontend thresholds only control display.

Set backend-only `TYPESAFE_API_KEY`. Optional `JEV_MODEL` defaults to the pinned `jev-1.13.0`; moving aliases are rejected. The response must match that pin and contain exactly five valid Score answers. A five-second total runner deadline includes transport, body reading and at most one retry for 429/529/502/503/504, respecting Retry-After if it fits. Missing credentials, timeouts or invalid responses return through the existing AI-unavailable/community fallback. There is no random fallback. Logs contain only model/version, duration, token usage and sanitized failure categories.

`GENERATOR_VERSION` combines the formulation version with the pinned model. Bump the formulation version after changing mapper/context/rubric semantics. Generator version remains provenance for new writes, not a freshness predicate. Existing cached scores remain usable until the one-month TTL expires or the payload changes; no migration or deletion is needed. `npm run ai:clear -- --confirm` remains available for explicitly clearing development scores only, preserving payloads and user data.

Research links and bounded findings live in the context template. The original and revised live fixture results, score deltas and unchanged three expectation deviations are recorded in `guides/jev-evaluation.md`. No fabricated weights, universal prevalence, video-level accuracy or AI-authorship claims are used. Metadata and embedded commands are delimited as untrusted evidence. Jev sees no transcripts, audio, frames, thumbnails, source comparisons or channel history.

## Verification

With the local API running:

- `npm run test:integration`: UUIDs, votes, ownership, signals, reports, OAuth code exchange, PKCE rejection, replay, scope enforcement, refresh, revocation and expiry.
- `npm run test:ai`: payload mapping, cold/warm/partial caches, cross-version reuse, one-month expiry, stale payload refresh, English/undetermined language gating, concurrent requests, raw retention, score constraints, atomic failure, DTO and HTTP capability/auth checks.
- `npm run test:jev`: deterministic mapper, context, transport, rubric fixtures and deadline/retry tests.
- `npm run test:jev:live`: actual Jev generation through the local overview endpoint, five persisted scores, payload reuse and warm-cache verification; temporary records are cleaned.
- `npm run eval:jev`: optional live human-rubric fixture comparison; reports deviations rather than asserting exact scores or calibrated accuracy.
- `npm run build`: production build and type checks.

Tests use temporary development-database records and clean them afterward. AI tests inject provider fixtures to avoid quota and network dependence. The extension's `scripts/verify-backend.mjs` tests actual unpacked Chrome, with a fixture only at the Google authenticated-session boundary, without screenshots.

## Deferred evaluator architecture

Keep the existing five-score DTO and schema for now. A future product decision could split AI-use evidence from textual filler and combine them deterministically; expose an independent evidence-coverage metric; or persist/expose Jev confidence and level distributions alongside evidence strength. These changes are intentionally deferred rather than encoded into the current scalar score. The critic's compatible formulation changes are implemented in `youtube-metadata-v2`. Fresh cached results are retained across formulation changes until their TTL expires.

`npm run eval:jev` compares the unchanged seven fixtures and expectations with the recorded v1 scores in `scripts/evaluation-baseline.json`, reporting score deltas and old/new deviations for evaluated fixtures; language-gated skips are reported separately. This historical comparison is descriptive; a single run does not isolate model variability or establish accuracy.

## English metadata gate

Before returning cached scores or evaluating new ones, `franc` detects the language of the full title plus description. Only `eng` proceeds to Jev. Other ISO 639-3 codes, including `und` for undetermined text, return `{ status: "unsupported_language", detectedLanguage }` through the shared discriminated union. This is a metadata-language heuristic, not a check of spoken video language; short/mixed/repetitive text can be misclassified. Tags and provider language hints do not override the check. Non-English/undetermined payloads are retained, but no inference request or new signal rows are produced.

The extension handles ready, unavailable and unsupported-language results separately while keeping community ratings and voting available. Evaluation applies the same gate and reports skipped fixtures separately rather than treating them as zero-scored successes. Historical evaluation reports predate this policy.

### Viewer-comment evidence

The canonical YouTube video resource is enriched with `commentThreads: { status, order: "relevance", items }`. The backend requests the first ten top-level threads using `commentThreads.list`, `part=snippet`, `maxResults=10`, and `textFormat=plainText`; it keeps raw thread resources, without the list envelope or replies. The filtered context includes only comment text and publication/update timestamps, excluding author identities, likes and reply counts. Disabled/failed requests remain explicit missing evidence and do not block video evaluation. Older payloads without this field remain valid with unavailable comments. The English gate still examines video title/description, not viewer language.

Comments are a selected, unverified sample, not community consensus or direct evidence of unseen video content. Specific reports can support a signal, but comments alone cannot exceed the middle rubric level; stronger scores require uploader-metadata corroboration. Empty samples, generic praise, insults, AI accusations and repeated comments do not establish quality. All provider text is untrusted and delimiter-escaped. The existing one-month AI cache and frontend contract remain unchanged.

To clear content, contributions and cached results while preserving signal definitions and auth configuration, run `npm run content:clear -- --confirm`. AI signal types remain code-defined; community signal rows retain their IDs.

Verification: `npm run test:youtube-comments` covers deterministic transport/fallback behavior; `npm run test:jev` covers mapping and rubric boundaries. `npm run test:youtube-comments:live` fetches a real English video and ten comments, then evaluates five signals without storing content. `TEST_YOUTUBE_VIDEO_ID` can select another fixture. `npm run test:jev:live` validates persisted comment-aware evaluation and warm-cache reuse through the overview endpoint.
